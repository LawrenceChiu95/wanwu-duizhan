# Lux3D 生成的模型（Wren，2026-10-26）

用 Aholo Lux3D 从一张照片生成、已经处理成和 `data/models/` 同规格的资产，可以直接进
`catalog.json` 和样机。接入由 @Sol 负责，这个目录只放资产和重跑脚本。

## 文件

| 文件 | 是什么 |
| --- | --- |
| `pan-lux3d.glb` / `lamp-lux3d.glb` | **轻量版**：减面到 3 万面、**没有贴图**（纯网格）、0.71 MB。给手机跑 |
| `pan-lux3d-pbr.glb` / `lamp-lux3d-pbr.glb` | **高模版**：Lux3D 原始网格（21–22 万顶点）+ PBR 贴图，20.1 MB / 17.2 MB。好看但大 |
| `pan.source.glb` / `lamp.source.glb` | 减面后、归一化前的中间文件（轻量版的来源） |
| `prepare.mjs` | 从上面两部分重新生成四个成品和两个 JSON。用法见下 |
| `catalog-entries.json` | 两条现成的 `catalog.items` 条目：凸包、bounds、弱点、体积、质量、来源 |
| `files.json` | 四个 GLB 的字节数、sha256、有没有贴图、回读校验偏差 |
| `RECEIPT.md` | 生成回执：任务编号、时间、设置、源图、原始文件位置和 sha256 |

两个成品共用同一份归一化矩阵和凸包，都取自高模版，所以轻量版的包围盒会略小于下面这张表。

## 已经量好的数

坐标是 **X × Y × Z，单位米**，Y 向上，Z 向前（和 `catalog.json` 一致）。

| | X | Y | Z | 凸包点数 | 体积（m³） | 质量（kg） |
| --- | --- | --- | --- | --- | --- | --- |
| `pan-lux3d` | 0.285 | 0.047 | 0.380 | 26 | 0.00236 | 6.38（金属 2700） |
| `lamp-lux3d` | 0.229 | 0.450 | 0.099 | 26 | 0.00604 | 5.74（塑料 950） |

最长轴按 0.38 m 和 0.45 m 归一，跟现有的 `pot`（0.38）、`lamp`（0.45）一致。
锅按 `broom` 的规矩把长轴转到 +Z（躺平、柄朝前）；台灯保持竖直不动。

## 接之前要知道的三件事

1. **凸包是实心的，锅的凹面会被填平。** 跟现有 `pot` 一样，质量按整块凸包算，所以锅出来 6.4 kg，
   实物大概 2–3 kg。这是已知的系统性偏大，不是这批模型特别重。要压下去只能改密度或按壳算。
2. **台灯的凸包把灯罩和底座之间的空档连成了一根柱子。** 打架时它是个实心柱子，不是「细腰的灯」。
   视觉和碰撞会有出入，但不会穿模，属于可接受的那一档。
3. **两个模型都是 Lux3D 从单张图生成的，拓扑不干净**（多壳、不封闭）。视觉和凸包都没问题，
   但不要拿去做别的几何运算（再减面、算真实体积、绑骨）。

## 重跑

```bash
# 依赖 rapier，先确保 sim/node_modules 存在（在 sim/ 下 npm ci）
node data/lux3d/prepare.mjs
```

脚本会自己回读写出来的 GLB，确认引擎读到的包围盒等于「源网格套上矩阵」的结果，对不上就报错。
高模版的原始导出不在仓库里（太大），路径在 `RECEIPT.md`。
