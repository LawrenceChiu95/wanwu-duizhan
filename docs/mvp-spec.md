## 2. 做什么、不做什么

**MVP 做**（第 4 步交付）：
1. 角色库：6–8 件默认角色，用生成脚本从凡朔的照片事先生成，每件可回放生成过程。不是照片生成的件（CC 模型、只有 GLB 的废土样品）只标来源，没有回放。
2. 拼装：从角色库挑两件，伸出或贴着，对面或挨着；对手由电脑配一套，看得见。
3. 对打：第 13 版冲挡规则，加下面 §3 的改动；首局有三句提示。
4. 结算：一句原因、几项本局数据、一句提示、重看、原样再来、换个装法再打。
5. 场地收小加围栏，陀螺在手机上显大。
6. 事件清单定稿，凡朔的画面照它接进来。
7. 现场拍照生成：拍照、认物、生成中、失败、好了这几屏接上真接口，生成好的东西不用重新构建就能进角色库、装上去打（D2，排在战斗之后）。

**不做**（第 5 步或之后）：冲分快慢（点按快冲、按住蓄力）、三个打法不同的对手逐个解锁、三件装、新品类、生人试玩调平衡、知识卡、多场景、真人对打、排行、装法存档。

## 4. 每一屏（打开到再打）

手机竖屏优先，电脑 1440 宽居中加两侧栏（沿用现在的版式）。Iris 出线框，凡朔定样式。

1. **第一次打开**：直接进拼装页，已装好一套默认装法，「开打」高亮。首局对打里出三句提示，每句一次：「按冲，朝它扑过去」「它冲过来时按挡，把它弹开」「件碎了，核心就露出来了」。以后不再出。
2. **拼装页**（主页）：
   - 顶部「VS 对手」：电脑那套两件（图标、名字、伸出或贴着），旁边「换个对手」。
   - 底部两个槽：点槽进角色库挑；每槽「伸出 / 贴着」；下面「对面 / 挨着」和「开打」。
   - 中间两颗陀螺慢转预览。
3. **角色库**（全屏，从槽点进来）：
   - 卡片网格：原照片小图（没有原照的显示来源，如「CC 模型」）、真 3D 慢转、名字、品类、最显眼的总 S–D、三行小字母「攻击 / 范围 / 耐久」，最后保留「N cm · M kg」；另一槽已装的标「已装」。
   - 照片生成的卡有「看它怎么来的」，其余没有。顶部显示各等级收集数，S 排前。生成完翻牌亮等级，S 有金光，翻牌有音效；按等级筛选和“新”标记交完以后做。拼装和结算给已装件标等级。
   - 顶部「拍一件」（D2，11-13 前接上；之前按钮先藏起来）。
4. **看它怎么来的**（回放）：一条三步进度：照片 → 改成画风的图 → 3D 转起来，旁边标品类（人选的，不写成模型认的）。约 10 秒放完，每步和总用时都从这件生成时的记录逐件读，不写固定数。按钮「装上它」回拼装页。
5. **拍一件**（D2，排在战斗之后，11-16 验）：拍照或选图 → 认物（几秒，显示「按锅算」，不能改）→ 生成中（四步进度、预计 1–2 分钟，可以「先去打一局」，好了顶部提醒）→ 失败（一句原因；「再试」只查同一任务、重新下载或重新处理；要重新生成，先明说会再扣一次额度，确认后才建）→ 好了（原照和 3D 并排，翻牌亮出该件等级，「装上它」）。
6. **对打**：沿用第 13 版（血条、件小牌、冲挡按钮和冷却填色、冲挡结果一个词、镜头三选一），加首局提示。陀螺按 §7 显大。
7. **结算**：
   - 大字「你赢了 / 你输了 / 平局」，顶行第几秒、怎么结束。
   - 一句原因（现有 8 种文案，加超时的）。
   - 本局数据最多三项：冲中几次、被挡几次、完美挡几次、先碎的是哪件，挑和这局输赢最相关的。
   - 一句提示，按规则模板出，例如：先碎的是伸出的那件，提示「试试把它改成贴着」；冲空多，提示「等它靠近再冲」。
   - 按钮：「重看」决胜一击、「原样再来」、「换个装法再打」。

## 5. 画面和物理之间的事件清单

- **真源**：`sim/v3.js`。Sol 在仓库写 `docs/EVENTS.md`，带版本号，取代 INTERFACE.md。改事件先改文档、升版本号。
- **凡朔的画面**：只读 `frames` 和事件，不改 sim、不改判定。碎件只做视觉，不参与碰撞；攻方和反震同一个 `t`，播成一次撞击；手动输入只走 `press()`。
- **事件**（现有的见素材 §6，R5 新加三个）：

| 事件 | 画面该做什么 |
|---|---|
| `start` | 开局横幅「开转」、首局提示 |
| `press` | 不处理 |
| `dash charge / go / end` | 蓄力、锁定方向箭头、扑出；结束时冲空、擦边、被挡 |
| `block`、`blockResult` | 护罩升起；完美、挡住、挡空了 |
| `contact` | 不处理（只是碰到，不扣血） |
| `hit` / `weak` | 撞击火花、震屏、命中名牌「X 撞了 Y」、暴击 |
| `recoil` | 不处理 |
| `parry` | 弹飞特效、金属声 |
| `break` | 件碎飞出，「你的 X 碎了」 |
| `ko` | 核心碎、横幅 |
| `ready` | 冲或挡按钮「好了」弹一下 |
| `result` | 进结算过场 |

- 「护住」（受击件是贴着的）、部件危险红光、结算原因句继续由画面自己推，不进事件。

## 7. 验收（第 4 步）

**远夏手机上，11-12 战斗部分**：从角色库挑一件，看它怎么来的 → 装两件 → 跟电脑打一局 → 看结算懂不懂为什么输 → 改装法再打一局。

**11-16 现场拍照**：拍一件身边的东西 → 认物（显示按哪类算，不能改）→ 等 1–2 分钟（可以先去打一局）→ 好了装上去打一局。中途关掉页面再打开，结果还在；失败了「再试」不重复扣费。

**数**（Sol 批量和 Wren 页面实测；不过线不交）。统计口径按 Sol 审查 B4、S2，同一批数据只有一种判法：
- **局长**：取 `meta.duration`。自动 A、自动 B、手动（固定按键策略）**分别**判：中位 25–35 s，超过 45 s 的局 ≤5%。三种不混在一起算。
- **首撞**：首次有效伤害（不是碰墙或只碰到），≤1 s；没有有效命中的局照样计入，不能从统计里消失。
- **择时**：沿第 13 版，固定六个场景、同一批种子和对手，六个「择时减乱按」胜率差的**中位 ≥15 点**；单场景结果一并列出（现在锅加扫把贴着只有 9 点，不要求每格过线）。
- **装法**：同两件、同对手、成对同种子，每次只改一处（某件伸出↔贴着，或对面↔挨着），这些单变量对比的胜率差中位 ≥5 点。不能拿换东西或只挑最好最差来代替。
- **默认 S 池（R8，本稿取代同品类同强）**：先冻结九件和 S 名单。S 单件的伸出/贴着、S 双件的两朝向与两间距均筛最佳装法；用独立成对种子验证，单件和双件分表，不混成一个胜率。双件正式复核 100 种子，保留完整种子簇区间；对其他 S 装法平均胜率区间下限仍高于 65% 的组合，11-12 前压下来。只在初选种子选装法，不能拿正式验证种子反复挑赢家。默认 S 池太少导致没有多个不同双 S 组合时，明确列出覆盖不足，另测其对九件的配对表，不宣称全部 S 搭配已平衡。三模式、择时、镜像和单变量装法仍分别验。原六类表和四组超线作为历史依据，不是本轮已经通过。
- **镜像**：沿用六场景、200 个种子、交换电脑随机流成对测；按玩家身份算，胜 1、平 0.5、负 0，**逐场景** 45–55%。
