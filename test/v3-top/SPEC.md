# 万物对战 v3-top：战斗陀螺 demo（10-27）

## 第13版：时机算数、开局对称（已定稿，实施中）

目标：固定节奏乱按不再和观察后出手一样强；位置、朝向和倾斜不靠开局抽签。只改 `sim/v3.js`、`sim/v3-rules.json` 和相关测试；画面提示由前端接事件实现。基于镜头切换修复e5b70fe及测量脚本bbaaeb7另开 `sol/v13-timing`，不把规则混进镜头交付，不改main或自行发布。Elara 3ece5f94已定稿开工，10-29 17:30合交、20:00前交付验证。

### 为什么这么改

目前 `tryPress` 使挡持续1秒，冷却5秒，整个窗口都按0.3倍伤害处理；`manualStep` 在蓄力结束才瞄准对方，冲刺加速度又继续追对方。只要冲刺碰到，便强制算攻方并在封顶后乘1.25。玩家几乎不用判断方向或接触时刻（`sim/v3.js:178–203,215–254`）。开局倾斜、Y/Z偏移都来自种子（62–76、164–169），六场景只换该随机流就有39%的局换赢家。该数表示同种子配对翻转率，不是“随机占胜负39%”。

### 挡：短窗口，早按会空挡

- 默认 `blockTime=0.25s`（30物理步），立即生效；`blockCooldown=5s` 不变，空挡也照扣。不另外加常驻防御或新的按键。另跑0.20/0.30敏感性；0.25不过15点先交冲突，不自行收窄。
- 只在真实新接触开始、该方成为受击方且有正伤害时判成功；窗口内第一次命中标一次“完美挡”。窗口内减伤0.3、受击反冲0.3，来冲的一方反冲2.6，沿用原值；防御不凭空回血，不延长到下一次接触。
- 一次窗口只给一次成功结果；结束没有挡中便给“空挡”。不会把“没有遭到攻击”武断标成“按早了”。前端可让护盾合拢并熄灭，不能播成成功弹反。接触前按、接触同一步按、到期那一步、冷却中连按分别有边界测试。
- 弹开仍须真实接触，不把擦着不扣血的持续段当新的成功。原 `parry` 只在实际冲被有效挡住时触发。

### 冲：按下时锁方向，碰上还要对准

- 保留蓄力0.3s、冲刺最长0.45s、速度5、速度上限5.5、冷却4.5s。按下时记录指向对方核心的水平单位方向，蓄力后沿这个方向冲；冲刺期间不再追踪转弯，竖直扶正和原碰撞保持。按在对手弹开、横移时容易冲空，蓄力阶段看得见方向。
- 只在首次真实新接触判定质量：锁定方向与当时朝对方核心方向的点积至少 **0.90**，且双方核心沿此方向仍在接近，才算正冲。方向和接近速度都取本次物理求解前的核心位置、线速度快照（补存核心位置，不用重心位置，也不读碰撞弹开后的速度），避免把撞后已分离错判为冲空。点积直接比较，不用三角函数。水平核心距离为0时记alignment=null，按普通偏冲处理，不强判满分或发NaN，测试覆盖此边界。
- 正冲才保留“冲的一方优先算攻方”和封顶后×1.25；单击普通最高37.5%、弱点最高50%仍不变。偏冲按原普通碰撞的攻守和伤害计算，没有额外冲刺加成，也不人为扣血。物品外形仍决定撞到哪件，真实冲量仍起作用。
- 第一接触结束这次冲：正冲、偏冲、被挡分别回报；时间到没碰到就是冲空。反冲强度的冲刺奖励也只给正冲，偏冲按普通反冲，避免不加伤害却仍靠强制弹开通吃。
- 不用陀螺旋转的道具朝向作“对准”尺子：当前每秒约转两圈，仅凭两键很难掐准那一瞬。这版判断的是玩家按下时选中的冲刺路线。

### 开局：两边相差半圈，不翻转道具网格

- 两核心原点固定在 `(-d/2,0,0)` 和 `(d/2,0,0)`，`d=两边原装扫过半径之和+0.35m`；初速度0、初始倾斜0。
- 左侧四元数 `[0,0,0,1]`，右侧 `[0,1,0,0]`（绕Y轴半圈），两边沿现有同向+Y轴转速12开始，现有 `spinDirections=[1,1]` 不变。同装法的碰撞外形、重心、角速度可通过这次半圈旋转一一对应。
- 这是中心对称摆放，具体落实“互相朝向对方”；不把手性道具做负比例镜像，不改变模型或挂位。Lead已确认这一“镜像”口径。
- 种子继续控制暴击和已有攻守同分裁定；不再影响初始几何。电脑按当前可见状态确定性决策。自动模式也采用对称开局，所以自动完整SHA会变，须保留旧版并存第13版新基线，不能伪称不变。
- 电脑只读开局当前姿态、位置/速度、可见蓄力和冷却。双方在同一0.1s观察节拍先各自决定、再一起应用按键，避免“先处理一方，另一方看到本步刚按的键”造成先后手偏差。输入侧仍按下一固定步收，不改按键录制契约。

### 电脑择时和给前端的字段

电脑用当前相对位置、速度与两边可见扫过范围估计首次接触剩余时间（平方、点积、sqrt），不偷看未来模拟或暴击。预计0–0.15s将受到接近的撞击且挡已就绪才挡；冲时用现有0.3s蓄力加直线冲刺外推，预期能碰上且方向点积达标才冲。不靠提高伤害、专属反应速度或减少冷却让电脑过线；去掉旧“看到蓄力就15%抽一次挡”的尺子，保留0.1s观察节拍。实际碰撞仍可与估计不符。

旧事件不删，新增字段只表达模拟已判定的事实：

| 事件 | 追加字段与触发点 | 前端用途 |
|---|---|---|
| `block` | 保留 `side,until`，加 `pressStep,windowSteps` | 护盾立即合拢、按实际挡窗消失，冷却独立走 |
| `blockResult` | `side,outcome:'perfect'\|'empty',pressStep,resolvedStep,point?,attacker?`；一次防御只发一次 | 成功白光/弹开或空挡熄灭；空挡不冒充“必定按早” |
| `dash` charge/go | 追加 `pressStep,lockedDir`，go的 `dir` 就是锁定方向 | 蓄力时显示将要冲的方向，go沿该方向表现 |
| `dash` end | 保留 `side,outcome,point?`，追加 `quality:'full'\|'glance'\|'miss'\|'blocked',alignment?,pressStep` | 正冲保留重打击，偏冲擦过，空冲收势；不是新增常驻说明 |
| `hit/weak` | `dash` 仅正冲奖励为true；追加 `dashAttempt,dashQuality,alignment`；`shield/parry` 来自有效挡窗 | 偏冲不套满伤害的火花/重音；画面不自行判物理 |

事件时间、delta和判定使用固定步；JSON只存有限数字/明确枚举，不记录浏览器时间。内部窗口状态不由前端写回。字段已交Iris确认；`manual.blockTime`可选0.20/0.25/0.30，写入`meta.manual.blockTime`，重放须传回。前端只用地址参数`?block=0.2`等，不增加界面开关；使用旧事件也应能正常显示基础对战。

## 做什么
1. **陀螺式挂法**（sim/）。核心球绕自己的「上」轴高速自转，赤道一圈有固定挂位（`v3-rules.json` 的 `top.slots`，每 45° 一个）。每件道具选一个挂位和一种朝向：
   - **伸出去**：最长的那条边沿半径朝外，最薄的那条边朝自转轴（像刀片平躺在旋转面里）。哪头朝外按品类写在 `top.outEnd`（扫把是刷头、锅是锅身、剪刀是刀尖）。
   - **贴着**：最长的边顺着自转轴竖起来，最薄的边朝核心，宽面贴住核心一侧（像盾）。
   - 两件不重复、挂位不重复；转起来只有「两件之间隔多少度」有意义，网页给「对面（180°）／挨着（90°）」两种。
2. **转起来**：开局就在转。自转靠一个有上限的力矩维持（重的、伸得远的转起来慢、被撞慢了恢复得也慢）；被撞歪了会慢慢自己扶正，旋转面大致保持水平，方便两边的刀片在同一个面里相遇。
3. **节奏**：保留「靠近 → 甩出去撞 → 弹开」：撞上后两边沿法线各弹开一下（反冲速度不低于 v1 的 0.85 m/s），停追一小段再追。新增：追击时消掉两边相对绕圈的切向速度（修掉件后的空转，原因是吸力和追击都沿连线、消不掉切向速度，两边一直错开）；位置校正每步限幅，去掉一次跳 27 cm 的径向搜索（修分离跳动）；伤害和血量一起调（修短局）。
4. **决定输赢那一下**：沿用慢镜头；回放里给出结构化的原因（谁的哪件、伸出去还是贴着、打中了核心还是道具、输家当时还剩几件），网页把它说成不超过 20 字的一句白话。
5. **网页 demo**（web/）：
   - 装配：选两件（锅、扫把、台灯、剪刀、拖鞋、枕头；锅和台灯用 Lux3D 生成的带贴图模型），每件点一下切「伸出去／贴着」，再点一下切「对面／挨着」；上方是自己这台陀螺的实时 3D 预览，点了马上变。默认装法直接能开打。对手是固定的电脑装法。
   - 对打画面：核心球发光、一眼可见；转动有拖影扇面；撞上有闪光火花；道具碎掉时模型从核心上脱落、碎片飞开；核心血和道具血用最少的小条表示，不堆文字。
   - 打完：一句白话原因 + 「换个装法再打」回到装配。
   - 手机竖屏为主，300 px 和 390 px 两种宽度验版面。
6. **发布**：Raft Artifacts `wanwu-top-demo`，游戏放 `play/`，首页一个大按钮；manualChunks 拆包分批发；发布副本加 `window.createImageBitmap = undefined;`；对外不带 agent 名和内部路径；可见范围不改。

## 加一个手动模式（10-27 晚加的范围）
- 来源：远夏 #万物对战:2db22844 里的 80a59794「冲和档都加吧，攒格子慢点加，现在可以做吗」；Elara 裁决 428deaf5。
- 自动版原样保留当对照：同样的装法，同一页上有清楚的「自动 / 手动」切换。
- 手动模式里陀螺照样自转、照样被中心吸，玩家只按两个键：
  - **冲**：点一下 → 约 0.3 秒看得见的蓄力（发光或下压）→ 整台陀螺明显比平时快地扑向对手，撞得更狠 → 冷却约 4–5 秒，按钮上一圈扫过去表示冷却。
  - **挡**：点一下 → 核心上约 1 秒看得见的护盾光，期间受到的伤害和击退大幅减少；挡住对方的冲时，那一冲明显被弹开，这一下要一眼看懂。冷却约 5 秒，显示方式同上。
- 电脑对手也会冲和挡：简单规则加一点随机，同一种子结果固定。
- 冲的伤害和单击封顶（Elara 10-27 晚裁决，起因 Sol d75073bd）：单击 30%、弱点 40% 的封顶管普通撞击；冲在封顶之后再 ×1.25，单击最多 37.5%、弱点最多 50%，满血核心仍至少要两下才碎。冲是玩家自己掐准的一下，封顶后不加就白按了。
- 主线不变：形状和位置还是决定打在哪里，按键只决定什么时候；同一套装法里仍要看得出是哪件打中的。
- 节奏验收线两种模式都要达标、分开报。回放仍要确定可复现，按键作为事件记进回放。
- 界面：底部两个拇指够得着的大按钮，图标加「冲」「挡」，照 frontend-design 的要求做。截图：390 和 1440 各一套，另加冲撞命中一张、挡住冲撞一张。

## 镜头（10-27 晚改，优先于手动模式）
- 来源：远夏 5740feda 手机上玩 v4 看晕了；Wren 在 390 宽实测（c489ef86 / 1bf701f1）：整帧平均 497 px/秒、最差一秒 907、8 秒里方向反转 39 次，37% 的帧对上下两半反向移动（镜头在转/滚）；Elara 裁决 98f93d28。
- 定了的：
  1. 固定镜头：开打后不跟、不转、不绕、不推拉。一个姿态：从上往下斜看（与水平约 60°），框住整个场地留一点边，两颗陀螺被撞到场边也整颗在画面里。取景只在开局（按两边装法的伸出长度）和窗口尺寸变化时算一次。
  2. 震屏只给决定性的一下（道具碎、核心碎）：几 px、不到 0.2 秒、只平移不转；拿不准就不加。
  3. 结算：镜头不动；只有赢家被结算卡挡住时，整幅画面向上平移一次（≥0.6 秒缓动，不转不缩）。决胜慢放只保留时间放慢，不动镜头。
  4. 陀螺在 390 宽显小，就给场地更多屏幕（版面），不动镜头。
- 过线（Wren 同一量法：点「开打」后 1.5 秒起，10 帧/秒截 8 秒，整帧相位相关，CSS px）：整帧平均位移 ≤40 px/秒；最差一秒 ≤150 px/秒；上下两半反向的帧对 ≤5%；位移 >30 px 的帧合计 ≤0.3 秒（震屏）；震屏只平移不转；场地边缘一圈和两颗陀螺始终在画面里。
- 自测脚本：`web/scripts/camera-motion.mjs`（截帧 + 整局安全区/场地边缘审计）+ `web/scripts/camera-motion.py`（相位相关），结果见 `RESULT.md`「镜头」。

## 不能退步
1. 撞上那一下的力度、撞完弹开的惯性：和 v1 球形版同种子比，撞击瞬间接触点相对速度、撞后 0.2 秒内两边分开的速度，中位数都不低于 v1。相对速度两版统一用撞前读法（R2：那段接触第一次有解算冲量之前的速度，算接触点沿法线的迎击速度，`test/v3-top/impact-probe.mjs`）；「不弱于 v1」以分开速度为主证据。
2. 慢扣血为 0：只有真实接触才扣血。
3. 连续刮蹭（持续接触 ≥0.1 秒）单独统计，持续段内的重复冲量不算新撞击。
4. Node 和 Chrome 回放逐字节一致（`test/v3/browser*.mjs` 照跑）。
5. 只有核心碎了才输；道具全掉也继续打。

## 验收（Elara 验收线）
- 节奏：一局 20–40 秒；开局到第一次有效撞击 ≤1.5 秒；有效撞击间隔中位 ≤3 秒、最长 ≤6 秒；慢扣血 0；连续刮蹭单独报。多种子 ≥50 局（10 分钟内跑完），报通过比例和不过的样子。
- 手感：v1 同种子并排，相对速度、分离速度不低于原来；附前后对照截图或回放。
- 平衡：不出现一件东西通吃，报各件胜率。
- 看得懂：画面能分出哪件伸出去在打、哪件贴着在挡；掉了一件以后局势变化看得出来（截图体现）。
- 网页：390 px 宽截四张（装配、撞上那一下、一件碎掉、结算），300 px 宽版面不溢出；Lux3D 模型有贴图；无长时间卡顿。
