# 缺评分的入口错误与统一读取

来源：频道 task #21，Elara a829fece 并入 PR27 第3、4条。Sol 做逻辑，目标 mvp/base。

- 三项评分必须同时是有限的0–100数字；缺整份、缺单项、NaN/Infinity/字符串/越界均无效，不用0或现场重算补齐。
- 复用评分模块提供的读取检查。模拟入口在创建世界之前检查已选物件，报出物件名字、ID和“缺评分或评分无效”；itemCombat 独立调用也明确报错，核心不需要道具评分。
- 页面 ratingOf 与结算提示共用同一已存评分读取；无效三项视作无评分/无偏好，不能落成“适合伸出”。不改界面布局或评分公式。
- 有效 catalog 评分、几何、物理系数和回放保持。只校验选中的件，未选坏条目不阻塞有效对局。
- 验收：缺整份/逐项缺失/坏数字，模拟入口和直接计算错误；页面与提示同源且无误判；原有效回放逐字节相同，原规则、跨平台导入和网页构建通过。

## task #28：显示字母与分数一致

- 三项有效分数是页面显示的依据。ratingOf 复用评分模块的 gradeFor，为三项各取字母、按未取整平均分取总等级；已存 letters/grade 缺失或不一致也不能把错误字母显示出来。保留原分数和版本，不修改传入物件，不重算物件分数。
- 删除“未选坏条目”用例末尾对注入前副本的无效断言，保留真实对局能创建的检查；标题只陈述实际验证的行为。
- 验收：0/100、五档边界、三项不等且平均未取整、错误或缺失字母、按纠正后等级排序；无效分数仍返回 null，战斗系数仍读取原分数。只改显示读取和测试，不改评分线、catalog 或战斗规则。
