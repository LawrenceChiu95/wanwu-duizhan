# 结算提示按具体件的长处判断

来源：channel task #17、Elara 3446654a；目标 mvp/base。Sol 只改提示判断，Iris 原界面和 tipLine 返回一句话的接口保持。

- 当前问题：范围型伸出件先碎，旧规则一律推荐改成贴着，会反着教玩家。
- 判断输入：该件 rating.scores 的攻击、范围、耐久，不按品类或总等级代替。
- 攻击或范围的较高分比耐久高超过5分：适合伸出；输局中若这类件贴着，建议伸出并换另一件贴着。伸出先碎时建议抓准挡的时机，不反转朝向。
- 耐久比攻击、范围的较高分高超过5分：偏守；伸出先碎时允许建议改成贴着。
- 两边相差5分以内（含5）、或该件缺三项记录：不臆造专长；伸出先碎时给挡的时机建议。
- 赢局文案、零输入引导、其余冲空/被挡等顺序保持；不改伤害、几何、胜负和评分。

验收：两个默认扫把伸出碎不推荐贴着；贴着的进攻型件落败推荐伸出；防守型伸出件碎仍可推荐贴着；同品类不同分可得不同建议；并列/缺分不捏造偏好；赢局和零输入引导不退步。纯函数测试遍历 catalog 全部 11 件真实物品（默认可选 9 件、旧模板 2 件）和隔离的小型反例，加入现有 CI。

Elara a829fece 将审查第2条裁为阻塞：另一件也擅长伸出时，不推荐把贴着的进攻件换出去，继续后续提示；两个真实扫把正反配法覆盖这一反例，其余六条建议另卡。

### 旧锅、旧台灯为什么保留

`pot`（锅，2.5 kg）和 `lamp`（台灯，1.5 kg）是旧模板，**不在当前可选九件中**，不应用来画当前卡片。现用锅是 `pan-lux3d`（2 kg），现用台灯是 `lamp-lux3d`（1.3 kg）。

- `web/src/main.js` 的 offerOf 按 comparisonBase 排除 pot/lamp；角色库、拼装选择和 mine/foe 测试链接共用这份 OFFER，默认装法和五套对手也都不用旧两件。正常玩家及合法链接拿不到它们。
- 仍有代码依赖：`tools/import-item/cli.mjs` 从同类、非 generated、非 comparisonBase 的条目取模板，锅与台灯当前正是旧两件；新导入件记录 templateId，继承材质、标签等模板事实。`sim/batch.js` 用它们作原件对照，仿真 API 也仍接受 catalog 中这些有效 ID。删除会改变导入与历史对照契约，超出本卡。
- 因此本批保留为旧模板，在此明确标识，不删除 catalog、不改名字或筛选逻辑。历史回放按原 ID 读取；默认九件展示、配平和物理口径不因此扩大为十一件。
